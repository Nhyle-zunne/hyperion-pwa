# Messenger manual payment claims

Approved behavior: a Google-signed-in checkout buyer presses one combined copy-and-Messenger action. Hyperion creates or reuses a *text-only*, account-owned, unverified claim for the selected cart and server-verified PHP total. The message includes the claim ID, account email, selections and amount. Customers attach their receipt only in Messenger, or identify themselves by Google account email. No image is uploaded to Supabase.

Claim states: `awaiting_proof` (button clicked, NOT proof of payment), `pending_verification` (admin matched a Messenger receipt, NOT proof funds cleared), `approved` (bank credit verified; atomic fulfillment), `rejected`, and `expired` (abandoned `awaiting_proof` after 72 hours). A claim never unlocks content by itself. The admin manually matches the receipt/email/claim and actual InstaPay/QR Ph credit before approval; no automatic bank verification is claimed. Anyone may initiate a claim without paying, so admin screens must label it clearly and require a separate proof-received action before approval. Repeated clicks on the same open cart reuse its claim; each user has at most three open carts.

The existing Admin Payment Submissions screen will gain a dedicated manual claims section and preserve prior PayMongo orders, reconciliation alerts and entitlements. Approval of multi-track carts is atomic; subscriptions stack on active expiry, lifetime tracks use a dedicated `manual` provider and hashed claim references. No PayMongo transaction/entitlement tables are deleted or rewritten. Checkout disabling is checked server-side for ordinary customers. Claims contain only metadata and admin notes, not the receipt.

Source of truth for the product pricing and validation is the service-role-only Postgres claim function. Edge Functions verify the session with Supabase Auth, and the admin function verifies the allowlisted admin email; no direct client writes to claims. RLS grants signed-in owners read access only. On clipboard failure checkout leaves the user a selectable message and explicit Messenger fallback rather than claiming successful copy.
